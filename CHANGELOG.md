# Changelog

## [Unreleased]

### Added
- **Media correctness regression tests (21 tests)** — `tests/test_media_correctness.py` generates a synthetic 6s/30FPS source via `ffmpeg -f lavfi`, runs `cut_and_concat` with both `segment` and `batch` methods, and asserts frame count / duration / r_frame_rate / A-V sync via `ffprobe -of json`. Coverage: original reproduction case (silence 2-4 → 4s/120 frames), CFR matrix at 24/25/30/50/60 FPS, silence at start / end, 10-segment drift accumulation, `audio_quality='high'` bitrate > `'low'`, `output_fps='60'` frame duplication, audio-less source handling. Skipped when ffmpeg/ffprobe aren't on PATH.
- **`audio_quality` preset** — `high` (256k), `medium` (192k, default), `low` (128k), exposed via `--audio-quality` / CONFIG_DEFAULTS / GUI. A 192k/256k/320k source is no longer silently downgraded to 128k without the user's choice. Plumbed through segment + batch + fallback paths; `_audio_bitrate()` and `_audio_opts()` centralise the AAC encoder options.
- **Safe encoder fallback policy** — `software_fallback = ask | disabled | enabled` (default `ask`). `ask` refuses silent fallback to libx264 when the requested HW encoder is unavailable or fails mid-run; the user must consent (CLI raises `EncoderUnavailableError` since it has no interactive consent handler; GUI wires a dialog). `disabled` raises immediately; `enabled` preserves the legacy silent-fallback behaviour.
- **`x264_preset` and `encoder_threads`** — `--x264-preset` (ultrafast..slower, default medium) and `--encoder-threads` (auto or positive int) cap libx264's CPU load. The `-threads N` flag is placed AFTER `-c:v libx264` so it applies to the encoder, not the decoder.
- **`output_fps` policy** — `source` (default, preserves input cadence without frame duplication) or `24`/`25`/`30`/`50`/`60` (force CFR conversion via `fps` filter; docs warn about file-size cost of duplicated frames). Verified by the media regression suite at 60 FPS (240 frames output for a 4s keep).
- **Resume manifest** — `_<stem>_segments/` and `_<stem>_batch/` working directories now contain a `_manifest.json` snapshot of (source path/size/mtime_ns, method, encoder, encoder_opts, video_quality, audio_quality, x264_preset, encoder_threads, keep_segments, pipeline_version). A mismatch wipes the work dir so old artifacts from an incompatible run cannot be reused. Each resumed segment/chunk is also ffprobe-validated for missing moov atoms (P0.6).
- **Download watchdog** — `_CONNECT_TIMEOUT` (5 min, first byte / DNS+TLS+handshake), `_NO_PROGRESS_TIMEOUT` (30 min, mid-download stall), `_DOWNLOAD_TIMEOUT` (8h, absolute ceiling). All three configurable via `--download-timeout` / `--connect-timeout` / `--no-progress-timeout` and `CONFIG_DEFAULTS`. The watchdog runs independently of `readline()` so a fully-hung ffmpeg is killed even when no stdout lines arrive.
- **Memory monitor** — optional `psutil`-based watchdog (`[monitor]` extra) in `stream2video/memory.py`. `MemoryMonitor` daemon thread polls the active subprocess's RSS every 2s; soft threshold (80% of `memory_limit_mb`) warns, hard threshold (95% or `available RAM < memory_reserve_mb`) cancels via the existing `cancel_callback` path. `memory_limit_mb='auto'` = 60% of total RAM at run start. Degrades to a no-op (with a one-time warning) when psutil is absent, preserving the historical behaviour.
- **Scoped process supervisor** — `set_active_process(proc, owner=...)` / `get_active_process(owner=...)` / `cancel_process(owner)` / `list_active_owners()`. The single-slot `_active_proc` was overwritten by parallel subprocesses (waveform preview + pipeline encode); the registry keys by owner so cancel/close targets the right one. Back-compat: callers that don't pass `owner` use the `"default"` slot, mirroring the historical behaviour.
- **Dockerfile for local Windows-to-Linux verification** — `Dockerfile` + `.dockerignore` build a `python:3.13-slim` + ffmpeg image that runs the full test suite (ruff + mypy + pytest). NOT for CI (the existing GitHub Actions workflow already covers that) — kept as a local convenience for Windows developers who want to verify their code in a Linux env without setting up WSL2 manually.
- **x264 low-memory preset** — new `--x264-low-memory` flag / `x264_low_memory` config option / GUI checkbox reduces x264 frame-buffer footprint via `-x264-params rc-lookahead=10:ref=1:bframes=0`. Produces slightly larger files but uses significantly less RAM during encode. Useful on memory-constrained machines (4-8 GB).
- **CLI memory limit flags** — new `--memory-limit-mb` (auto or MB cap, default auto=60% total RAM) and `--memory-reserve-mb` (default 2048 MB) flags passed through to the pipeline encoder. The CLI now also respects the config file's `memory_limit_mb` / `memory_reserve_mb` keys.
- **Dynamic batch chunk size** — `_BATCH_CHUNK_SIZE` is now scaled down for large segment counts (>200 segments) and long total duration (>3600s) to reduce per-chunk RAM pressure. Minimum floor of 5 segments per chunk prevents degenerate tiny chunks.
- **Memory reserve guard before pipeline phases** — `PipelineController.run()` checks `_available_ram_mb()` against the configured reserve before starting silence detection and the concat phase, refusing to start when available RAM is too low.
- **Pipeline phase timeouts centralised in CONFIG_DEFAULTS (P3.4)** — previously module-level constants in `concat.py` / `silence.py` / `waveform.py` are now exposed via `CONFIG_DEFAULTS` with `CONFIG_RANGES` validation and `USER_DEFAULT_KEYS` persistence: `segment_encode_timeout` (600s), `final_concat_timeout` (86400s), `silence_timeout` (36000s), `stall_kill_timeout` (300s), `stall_warning_timeout` (120s), `waveform_timeout` (300s), `batch_chunk_size` (40), `min_part_bytes` (1024). Seven new CLI flags (`--segment-timeout`, `--final-concat-timeout`, `--silence-timeout`, `--stall-timeout`, `--waveform-timeout`, `--batch-chunk-size`, `--min-part-bytes`) and GUI config wiring allow runtime override without code edits. Module-level constants remain as defaults for direct callers. Dead code `_HYBRID_SEEK_OFFSET` / `_AUDIO_PAD` removed (unused since P0.4).
- **Download / resume test matrix (fix-plan section 4)** — 33 new tests covering: progress parsing edge cases (zero speed, unknown total, ETA NA, zero downloaded bytes), network error classification (offline / DNS failure / timeout / retry-exhausted mapped to `DownloadError` subclasses, verified they don't misclassify as `VideoNotAvailableError` or `DiskSpaceError`), resume manifest validation (encoder change, quality change, source swap with same filename, keep_segments change, pipeline_version change, missing manifest, corrupt manifest JSON), source identity (path/size/mtime_ns capture, distinct files produce distinct identities), ffprobe corrupt-MP4 detection (truncated file, random bytes — the crash-mid-encode scenario), and pipeline controller Tk-isolation (static guard that `pipeline_controller.py` doesn't import `tkinter` / `customtkinter` / `PIL`, ensuring the worker thread can't call widgets directly).
- **Pure helpers extracted from GUI** — `stream2video/gui_helpers.py` (`build_cli_command`, `build_download_status`, `build_eta_tail`, `build_overall_line`, `build_silence_info_line`, `build_waveform_view_label`, `truncate_status`, `should_update_status`) + `stream2video/gui_widgets.py` (`Tooltip`) + `stream2video/gui_log_handler.py` (`QueueHandler`). 28 unit tests in `tests/test_gui_helpers.py` cover the formatting / decision logic without needing Tk.
- **`SilenceParser` unified state machine** — the three divergent silencedetect parsers (`_parse_ffmpeg_output` batch, `_run_silencedetect._on_line` progressive, `detect_silence_stream` inline loop) are now unified into a single `SilenceParser` class with `feed(line)` / `finalize(duration=...)`. The decimal-comma bug (P1.13) arose precisely because the three parsers drifted; consolidating them prevents the next drift.
- **Resume on cancel / crash for silence detection** — `detect_silence(resume_cache_path=...)` checkpoints the in-progress segment list to `{stem}_silence_cache.json.resume` every 30 seconds OR every 100 new segments (whichever fires first). On a subsequent run, if the file is fresh (mtime >= source mtime) and config-matching, ffmpeg is invoked with `-ss <last_segment_end>` to fast-seek past the already-detected work, and the returned list concatenates the pre-seeded initial segments with the new ones. The resume file is unlinked at the start of every detection (so retries inside the same call don't re-load it), kept on cancel/error (next run picks it up), and unlinked by the GUI on success (the final cache is the source of truth). Resume is not used for the bounded 60s sample-verify pass, nor for the just-extracted-WAV D path (the WAV was re-extracted, so old state is no longer in sync). The CLI now wires `resume_cache_path` (P1.8) so Ctrl+C mid-detection picks up from the last checkpoint instead of restarting from t=0.
- **Live waveform preview during pipeline run** — the GUI's waveform popup now reads from an in-memory `dict[Path, list[SilenceSegment]]` that the pipeline worker updates through `detect_silence(on_segment=...)` as `silence_end` lines arrive from ffmpeg. Open the Waveform popup mid-detect and the silence overlay grows in near real-time; the popup polls the in-memory store once per second and stops automatically when the pipeline finishes (`self.running` flips to False). No partial cache file is written — the canonical final cache at `{stem}_silence_cache.json` is still produced for cross-process / persistence.
- **Dry-run preview** — when the waveform popup is opened on a source with no cache and no live store, it now calls `detect_silence_stream()` instead of showing "No silence cache — run the pipeline first". The overlay appears immediately with the current threshold/min_silence/margin; the result is NOT written to the final cache (the user must still run the pipeline to commit).
- **Waveform popup: zoom + horizontal pan** — three zoom buttons (`-` / `1x` / `+`) and a pan cluster (`<` / slider / `>`) sit on a new controls row between the status line and the image. Zoom is **cursor-anchored** (the time under the mouse stays at the same pixel when zooming in/out) and falls back to view-center when the cursor hasn't been over the image yet. The pan slider scrubs through the full timeline at the current zoom level; the pan buttons shift the view by 25% of the view duration. Both are clamped: zoom to `[0.5s, duration]`, pan to `[0, duration - view_duration]`. The status line shows the current view range (`HH:MM:SS-HH:MM:SS`) and zoom multiplier (`1.5x`, `15x`), and updates live as the live poller detects new silences.
- **Streaming waveform (chunked downsample)** — `read_peaks_from_stream` reads 64KB chunks and downsamples online into a fixed-size peak buffer (256 samples/bucket), then max-pools down to `target_buckets`. Peak memory is bounded by `_READ_CHUNK_BYTES` + peaks list regardless of input duration (was ~230MB/2h, ~690-920MB/6-8h under `proc.stdout.read()`).
- **Audio-only output formats (mp3/opus/aac/wav/flac)** — new `--output-format` flag / `output_format` config key / GUI combobox. When set to anything other than `video`, `cut_and_concat` short-circuits the video pipeline entirely: the video stream is dropped, each keep segment's audio is re-encoded into the chosen codec (libmp3lame / libopus / aac / pcm_s16le / flac), and the per-segment files are joined by the concat demuxer (mp3/opus/aac/wav) or the concat filter (flac, whose muxer misreports duration on a concat-demuxer join). `audio_quality` controls the bitrate on lossy formats; lossless (wav, flac) ignore it. The output filename extension follows the format (`.mp3`, `.opus`, `.m4a`, `.wav`, `.flac`). `OUTPUT_FORMAT_SPECS` in `config.py` is the single source of truth for codec / extension / lossless flag / extra encoder opts.
- **Non-AAC input audio regression tests** — `test_non_aac_input_audio_normalized_to_aac` (libopus + libmp3lame in mkv, segment+batch) verifies the pipeline decodes Opus/MP3 input and re-encodes to AAC stereo without frame loss / A-V desync. `test_channel_layout_normalised_to_stereo` (mono/stereo/5.1, segment+batch) verifies the `-ac 2` normalisation. `test_non_zero_start_pts_normalised_to_zero` + `test_shifted_pts_long_offset_survives` (`-itsoffset 5.0` and `30.0`, segment+batch) verify the batch path compensates non-zero container `start_time` (found + fixed a real bug: batch produced 0-31 frames instead of 120 on shifted-PTS sources because `-copyts` preserved the shifted PTS but `trim={s}:{e}` matched source-time coordinates; new `get_video_start_time()` helper probes once and shifts both `seek_to` and trim endpoints).
- **Gapless audio concat (`--gapless-concat`)** — new `gapless_concat` config key / CLI flag / GUI checkbox. When enabled, the segment path's final join uses the `concat` filter (re-encode both video and audio through a single pipeline) instead of the `concat` demuxer (stream copy). The demuxer preserves per-segment AAC encoder priming (~21ms at 48kHz), which accumulates as A/V drift on multi-segment outputs — 10 segments drift ~170ms. The concat filter re-encodes through a single PCM pipeline so priming is added only once (not per-segment), giving gapless audio. Trade-off: video is re-encoded (one generation of quality loss); for lossless video + gapless audio, use `cut_then_encode` instead (one encode pass total, but sacrifices frame accuracy via keyframe snap). Default off preserves the historical behaviour (concat demuxer, faster). `_run_gapless_segment_concat` in concat.py implements the filter graph. 3 media correctness tests verify A/V drift bounds, frame count preservation, and single-segment demuxer fallback.
- **Lower process priority (`--low-process-priority`)** — new `low_process_priority` config key / CLI flag / GUI checkbox. When enabled, every spawned ffmpeg subprocess is started at a lower scheduling priority so a long-running encode doesn't starve interactive applications. On Windows, `subprocess_kwargs(low_priority=True)` composes `CREATE_NO_WINDOW` (0x08000000) with `BELOW_NORMAL_PRIORITY_CLASS` (0x00004000) into `creationflags`; on POSIX it sets `preexec_fn` to `os.nice(+10)`. The flag is plumbed through `cut_and_concat` → `_run_with_fallback` → every `_run_ffmpeg` / `_run_final_concat` / `_run_audio_extract` / `_run_audio_concat_filter` / `_run_gapless_segment_concat` / `_run_segment_concat` / `_run_cut_then_encode` / `_run_batch_concat` call (the cut phase's bare `subprocess.run(...)` in `_run_cut_then_encode` also received `subprocess_kwargs(low_priority)`) so per-segment encodes, the final concat, audio-extract intermediates, and chunk encodes all inherit the lower priority. Default off preserves the historical behaviour (normal priority, faster encoding). 5 unit tests (`TestSubprocessKwargs`) verify flag composition across platforms, and 1 media correctness test (`test_low_process_priority_produces_valid_output`) confirms the segment path produces a valid MP4 with `low_process_priority=True`.

### Changed
- **Pinned Python 3.13 as project default** — `.python-version` and CI use 3.13; `requires-python`, `ruff target-version`, and `mypy python_version` are now all `py313`/`>=3.13` (previously they were `3.11` while `.python-version` and CI used `3.13` — the targets had drifted). `mypy check_untyped_defs=true` enabled (was false), surfacing real bugs in `download._drain_stdout` / `_drain_stderr` (iterated `process.stdout`/`.stderr` without a None guard) and in `gui.py`'s waveform-window methods.
- **`segment` path: single input-side seek** — removed the double-seek (input `-ss` + output `-ss`) and the `setpts=N/FRAME_RATE/TB` resync. The new pipeline uses a single input `-ss {start}` + `-t {dur}` for frame-accurate cuts (verified: 6s/30FPS source with keep=[(0,2),(4,6)] produces 4.02s/120 frames, was 4.72s/135 frames). The `apad,atrim=duration=dur+pad` audio filter is gone — `-t` bounds both streams at `dur` so no per-segment drift accumulates.
- **`batch` path: trim+concat filter** — replaced the `select='between(...)+...'` + `setpts=N/FRAME_RATE/TB` graph with a `trim`+`concat` filter chain. The `select`+`setpts` graph produced a VFR-style timeline with a 1-second freeze where the silence was (5.03s/122 frames instead of 4.00s/120). The new graph is gapless CFR. The `[v][a]concat=n=1:v=1:a=1` no-op is also gone.
- **`batch` windowed decode** — each chunk now uses input-side `-ss` (coarse seek to chunk_start) + `-copyts` (preserve source PTS so the absolute-time `trim` filters still match) + `-t` (cap demuxer). Previously every chunk re-decoded the entire source from t=0; on a 6h stream with 100 chunks that was 600h of wasted decode.
- **`best` download quality** — changed from `best[ext=mp4]/best` (single pre-merged file, often 720p even when 1080p video-only exists) to `bestvideo+bestaudio/best[ext=mp4]/best` (separate audio+video, fallback to pre-merged). Better codec / quality on YouTube; pre-merged fallback covers sites without separate tracks.
- **yt-dlp progress template** — switched from `%(downloaded_bytes)s|%(total_bytes_estimate)s|...` to `%(progress.downloaded_bytes)s|%(progress.total_bytes)s|%(progress.total_bytes_estimate)s|...`. Old yt-dlp accepted bare names; current yt-dlp (verified 2026.03.17) treats them as attributes of the `info` dict and emits `NA` — the UI showed "?" for speed/percent/ETA despite the download running fine. `total_bytes` (Content-Length) is preferred over the estimate when both are present.
- **`detect_silence()` defaults** — now read from `CONFIG_DEFAULTS` (`-30 / 2.0 / +0.5`) instead of the divergent `-20 / 0.5 / -0.5` literals. A direct API call no longer cuts more aggressively than a config-file run on the same source.
- **`check_encoder("libx264")`** — now runs the real 1-frame smoke test instead of short-circuiting to `True`. Catches ffmpeg builds with libx264 stripped (rare, but the safety net must actually verify).
- **CLI `typer.Option` defaults** — read from `CONFIG_DEFAULTS` instead of duplicating the values as string/int literals. A future `CONFIG_DEFAULTS` edit propagates to the CLI help text and `--help` default display automatically; the two can no longer drift.
- **CLI progress formatting** — `_download_progress_cb` now calls `build_download_status()` from `gui_helpers` instead of rolling its own percent/speed/ETA string. CLI and GUI produce identical status-line formatting for the same yt-dlp progress event.
- **`logging.basicConfig()`** — moved from `cli.py` import time to the `main()` entry point so importing `stream2video.cli` (tests, GUI embeds, host applications) no longer hijacks the root logger.
- **Waveform preview is now pipe-only (no file I/O)** — replaced the WAV extract + cache save path with a single-ffmpeg pipe approach. Peaks are read from `ffmpeg ... -f s16le -ac 1 -ar 16000 pipe:1`, and silence detection runs directly on the source video via `silencedetect` filter to stderr. No `{stem}_audio.wav` is written, no `silence.json` cache is updated by the preview. The next real pipeline run still does the cached extract on its own schedule.

### Fixed
- **P0.1 segment double-seek** — input `-ss` + output `-ss` cut ~0.5s off each segment after t≈0.5s. Single-seek pipeline now frame-accurate.
- **P0.2 `setpts=N/FRAME_RATE/TB`** — `FRAME_RATE` is the source's nominal constant and disagreed with actual cadence on VFR / many CFR sources (30 FPS came out as 25 FPS, dropping 18-31 frames per 6s). Replaced with `trim`+`concat` filter chain (gapless CFR, frame-exact).
- **P0.3 audio always re-encoded to AAC 128k** — `audio_quality` preset now user-selectable; 192/256/320k sources no longer silently downgraded.
- **P0.4 `_AUDIO_PAD=0.1` per-segment drift** — `apad,atrim=duration=dur+0.1` added 100ms per segment; on 100 segments that's 10s of accumulated drift. Removed — `-t` bounds both streams at `dur`.
- **P0.5 silent fallback to libx264** — `software_fallback='ask'` (default) refuses silent fallback; the user must consent before a CPU-heavy encode runs.
- **P0.6 resume segments not tied to source/settings** — `_manifest.json` validates source identity (path/size/mtime_ns), encoder, encoder_opts, quality, keep_segments, pipeline_version. Mismatch wipes the work dir. Each resumed chunk is ffprobe-validated.
- **P0.7 yt-dlp progress template** — `progress.*` prefix now used; speed/percent/ETA populate correctly.
- **P1.1 download watchdog** — `_CONNECT_TIMEOUT` / `_NO_PROGRESS_TIMEOUT` catch hung connections before the 8h ceiling.
- **P1.4 batch re-decodes source per chunk** — `-ss` + `-copyts` + `-t` window each chunk.
- **P1.5 stall detector blocked on readline** — independent watchdog thread polls `last_progress_time` outside the readline loop.
- **P1.9 CLI cancel vs concat failure** — `except CancelledError` now caught before `except ConcatError` (subclass order).
- **P1.10 Tk widget reads from worker thread** — `delete_after` and other widget values snapshotted in main thread, passed as args to `_pipeline_worker`.
- **P1.12 trailing silence lost** — `SilenceParser.finalize(duration=...)` closes a `silence_start` without `silence_end` at the media duration.
- **P1.13 decimal comma in `detect_silence_stream`** — `_to_float()` now used everywhere (was `float()` in the progressive path, which raised `ValueError` on comma locales).
- **P1.14 no stream mapping policy** — explicit `-map 0:v:0` + `-map 0:a:0?`; audio-less sources produce a valid video-only MP4 instead of failing with "Output file does not contain any stream".
- **P1.15 waveform loaded entire PCM** — chunked reading bounds peak memory regardless of duration.
- **P1.16 waveform preview no dry-run** — `detect_silence_stream()` runs when no cache/live store exists; overlay appears immediately.
- **P2.9 `logging.basicConfig()` at import time** — moved to `main()` entry point.
- **P2.10 dead doc refs** — `_get_resume_cache_path` (never existed) and `read_waveform_peaks` (removed) references cleaned up.
- **P2.15 `v` already-defined in `cli.load_config`** — loop-local variable renamed.
- **GUI launcher `run_gui.cmd` didn't install Pillow** — the import check at line 47 only verified `stream2video` and `customtkinter`. The GUI then silently crashed on `from PIL import Image` because `pythonw.exe` has no console to show the traceback. Added `PIL` to the check so a clean portable venv installs the full `[gui]` extra set.

### Added

Lets users tune `threshold` / `min_silence` / `margin` visually instead of running a full encode. ## [0.2] - 2026-06-06

### Added
- **Audio-only silence detection with WAV cache** — first run extracts a 16kHz mono WAV and runs silence detection on it instead of decoding the full video. Subsequent runs skip the extract and re-run on the cached WAV. A 60s sample-verify on the source catches broken-timestamp videos and falls back to full re-detection. Significantly faster on long videos. The cached WAV is the same format the upcoming STT phase will need, so the extract step won't be repeated there.
- **Per-video project directory (`per_video_dir`)** — opt-in (on by default) mode that groups all artifacts (downloaded source, audio cache, silence cache, compressed output, log file, temp dirs) into a single `{output_dir}/{stem}/` subdirectory. Local source files are never moved or copied.
- **Recent Projects panel (GUI)** — left info panel shows the 5 most recent project directories. Click the label to open in the system file manager, click `X` to confirm-and-delete the whole project dir. List persists across restarts; rows truncate long filenames with `…`.
- **User defaults (`user_defaults.json`)** — new "Save current as defaults" button writes current tunable settings to a separate file; "Restore defaults" now uses these instead of always reverting to factory defaults. Per-session state (output dir, recent projects, input path) is intentionally not saved.
- **Final summary on completion (GUI)** — status line, log block, and completion popup now show source/output size and duration in a `X -> Y` format. `?` is used for any unmeasurable field.
- **Status line `elapsed / remaining` and overall wall-clock timer (GUI)** — per phase the status line shows `elapsed / ETA`; the bottom row has a live `Elapsed: X | Remaining: Y` label that freezes at the final total when done.
- **`--per-video-dir` / `--no-per-video-dir` CLI flag** — override the YAML config's `per_video_dir` setting per-run.

### Changed
- **Default: `per_video_dir: True`** (was `False`) — most users want every video in its own folder.
- **Default: `threshold: -30.0`** (was `-60.0`) — more typical "speech" threshold, cuts clear pauses without eating quiet consonants or background hum.
- **Compact action row + slimmer window (GUI)** — Start/Cancel buttons narrowed, step label moved next to them, progress bar shrunk to ~17% of the row width, default window 1250 → 1080.
- **Restore Defaults now respects saved user values** — previously, "Restore Defaults" would override saved `force`, `per_video_dir`, and `delete_after` with hardcoded deselects; now it correctly reads from the current settings.

### Fixed
- **GUI was always re-running full silence detection** — the GUI didn't pass `output_dir` to `detect_silence()`, so the WAV cache was never used. Now the GUI benefits from the cache like the CLI does.
- **WAV cache invalidated on long silences** — silence segments crossing the 60s verify window no longer cause a false-positive cache invalidation.
- **"Step 2/3" dropped on fast transitions** — terminal status messages (`Complete!`, `Cancelled`, `Failed`, `Error`, and step transitions) now always display even when the pipeline finishes quickly.
- **Step label could be pushed off-screen** — the action row is now in a separate grid column with `weight=1` so the step label always gets the remaining width.
- **Log said "Phase X/3" while status said "Step X/3"** — both now use the same word.
- **Recent Projects: various fixes** — eager persist on add, file-existence pruning, click-to-open, confirmation before delete, filename truncation.
- **GUI status label hard cut-off** — long status strings (e.g. progress with elapsed/remaining) were silently truncated mid-word at 50 chars; now end with `…`.
- **Recent Projects only tracked with `per_video_dir=True`** — output directories now appear in the panel regardless of the checkbox state.
- **GUI crashes on a hand-edited `settings.json`** — wrong-typed values are now silently dropped instead of crashing the slider/entry later.

## [0.1.1] - 2026-06-04

### Fixed
- **Margin semantics** — `_apply_margin` docstring was backwards; positive margin now correctly shrinks silence (keeps more audio around phrases), negative expands it. Default changed from `-0.5` to `+0.5` so phrases are no longer clipped.
- **AAC encoder lookahead loss** — `segment` method added `-af apad` + extended `-t` by `_AUDIO_PAD = 0.1s` so AAC encoder can flush its lookahead buffer at segment boundaries; previously the last ~20-50ms of each segment's audio was being lost.
- **GUI slider precision** — `number_of_steps` now derived from range (`round((max - min) * 10)`), so sliders land on exact 0.1 increments instead of values like `-25.1` when user wants `-25`.
- **`on_entry_confirm` rounding** — entry field value is now rounded before being applied to slider and config, so entry/slider/config stay in sync.
- **Entry → config sync** — added `_sync_slider_entries()` called before pipeline start; previously, editing an entry field and clicking Start without pressing Enter would use the old value.
- **Status throttling** — terminal status messages (`Complete!`, `Cancelled`, `Failed`, `Error`) now use `force=True` to bypass 0.5s throttling; previously the final "Complete!" was dropped when the pipeline finished quickly.
- **Missing Step 2 in pipeline** — silence detection block was inadvertently removed during refactoring; restored.

### Added
- **`--delete-after` CLI flag** — parity with GUI `chk_delete` checkbox; deletes downloaded source after successful compression.
- **Resolved output path in GUI** — `lbl_output` label in info panel shows the absolute output directory after pipeline start, so user sees where the file will be saved even when the field is empty and `./compressed_videos` default is used.

### Changed
- **Defaults** — `method=segment`, `encoder=h264_mf`, `threshold=-60.0`, `min_silence=2.0` (was `batch` / `libx264` / `-20` / `1.0`). These are the softest possible values — almost no cutting by default.
